# 접근성 점검 — KWCAG 2.2

한국형 웹 콘텐츠 접근성 지침 2.2의 33개 검사항목으로 이 사이트를 점검한 기록입니다. 첫 점검의 미흡 2건을 고친 뒤 같은 방법으로 다시 점검했습니다. 재점검에서 첫 점검 때 놓친 대비 문제 2건이 새로 나왔고, 이것도 고친 뒤 다시 확인했습니다(아래 '수정 기록').

## 점검 기준

- **표준**: 한국형 웹 콘텐츠 접근성 지침 2.2 (KS X OT0003:2022). 표지에는 방송통신표준심의회, 2022년 12월 28일 개정으로 적혀 있습니다. 4개 원칙, 14개 지침, 33개 검사항목으로 구성됩니다(표준 표 1).
- **확인 방법**: 표준 원문 PDF(52쪽)를 직접 읽고 표 2~5의 검사항목 번호·이름과 각 항목 본문을 대조했습니다. 아래 결과표의 항목 번호와 이름은 원문 표에서 옮겼습니다.
- **판정 규칙**
  - 통과: 점검한 모든 화면에서 요구사항을 충족함
  - 미흡: 한 곳이라도 충족하지 못함
  - 해당 없음: 항목이 다루는 콘텐츠(표, 동영상, 인증 등)가 없음
- **미확인**
  - 원문 PDF는 웹에이전시 사이트(websoul.co.kr)에 게시된 사본입니다. 표준 배포처인 국립전파연구원(rra.go.kr)의 원본과 같은 판인지는 대조하지 못했습니다.
  - 한국지능정보사회진흥원 웹 접근성 사이트(wa.or.kr)는 점검 시점에 접속이 끊겨(연결 재설정) 그곳의 해설 자료와 대조하지 못했습니다.
  - 인증 심사 기관의 세부 판정 기준은 확인하지 않았습니다. 이 문서의 판정은 표준 본문을 기준으로 한 자체 판단입니다.
  - 점검 브라우저는 Chrome 하나입니다. 다른 브라우저(Safari, Firefox)에서의 동작은 확인하지 않았습니다(6.1.1 메모 참고).
- **보조 점검**: 33개 검사항목 중 '확대 시 가로 스크롤(리플로)'과 'prefers-reduced-motion'을 직접 다루는 항목은 없습니다(원문 확인). 그래서 이 둘은 결과표와 별도로 기록했습니다. 참고로 앞의 것은 WCAG 2.1의 1.4.10 리플로에 해당합니다. 뒤의 것은 WCAG 2.1의 2.3.3 상호작용 애니메이션(AAA)과, KWCAG 6.2.2 정지 기능 제공에 가깝습니다.

## 도구와 방법

| 도구 | 버전 | 용도 |
| --- | --- | --- |
| axe-core | 4.14.0 | 자동 점검. 태그 `wcag2a` `wcag2aa` `wcag21a` `wcag21aa` `wcag22aa` `best-practice` |
| Chrome (headless) | 155.0.8059.84 | 점검 브라우저 |
| playwright-core | 1.64.1 | 브라우저 조작(화면 크기, 키보드 입력, 움직임 줄이기 설정 흉내) |
| html-validate | 9.7.1 | 빌드 때 미리 그린 HTML 18개의 문법 검사(`html-validate:standard` 프리셋) |
| 자체 Node 스크립트 | — | 아래 수동 점검 보조 |

- **자동 점검**: 화면마다 데스크톱(1440×900)과 모바일(375×812) 두 크기에서 axe를 돌렸습니다. 스크롤로 나타나는 요소가 보이도록 페이지 끝까지 한 번 스크롤한 뒤 실행했습니다.
- **수동 점검을 돕는 스크립트**(저장소에는 넣지 않음)
  - Tab 키만 눌러 초점이 가는 순서를 기록하고, 숨은 요소나 화면 밖으로 초점이 가는지 확인했습니다.
  - 초점이 있을 때와 뺐을 때 화면을 비교해 초점 표시가 보이는지 쟀습니다.
  - 키보드만으로 조작하며 상태를 기록했습니다. 대상은 목차 대화상자, 목차에서 챕터 이동, 각주 팝오버, 풀린 실밥과 알림, 사이즈 미선택 오류, 장바구니 대화상자, Inside Out 단서 넘기기입니다.
  - 320px(1280px 화면을 400% 확대한 너비)와 640px(200%)에서 가로 스크롤이 생기는지 확인했습니다.
  - 375px에서 링크·버튼 크기를 재서 표준이 권하는 대각선 6.0mm(약 22.7 CSS px) 미만인 것을 찾았습니다. 재점검부터는 상자가 작은 요소의 실제로 눌리는 범위를 `elementFromPoint`로 다시 잽니다.
  - 움직임 줄이기(`prefers-reduced-motion: reduce`) 설정을 켠 화면과 끈 화면을 비교했습니다.
  - axe가 판단하지 못한 명도 대비(패턴·그라데이션 배경 위 글자)는 화면 캡처로 다시 쟀습니다. 글자를 투명하게 만든 화면과 원래 화면을 비교해 글자 획 아래 배경 픽셀만 고르고, 하위 5% 대비값으로 판정했습니다.
  - 재점검에서 추가한 확인이 세 가지 있습니다. (1) 스크롤 연동 도식을 화면 가운데·위쪽에 두고 글자 요소의 실효 투명도(조상 포함)를 쟀습니다. (2) 고정(sticky) 구간은 121단계로 훑었습니다. (3) 도식 안의 SVG 글자 51개를 모두 쟀습니다(아래 '측정 방법 정정' 참고).
- **재점검**: 수정 뒤 위 도구와 스크립트를 그대로 다시 돌렸습니다. 타입 검사(`npm run typecheck`)와 빌드도 통과했습니다.
- **측정 방법 정정**: 첫 점검의 대비 재측정은 SVG 글자에서 글자색을 `fill`이 아닌 `color`로 읽었습니다. 그래서 SVG 글자의 대비를 실제와 다르게 계산했습니다. 재점검에서 이를 바로잡자 첫 점검에서 놓친 미흡 2건이 나왔고, 고친 뒤 같은 방법으로 다시 확인했습니다. 분해도처럼 진행 구간이 화면 너비마다 다른 도식은 진행률 1이 되는 위치(데스크톱은 고정 구간 끝, 375px는 도식 아래쪽이 화면 절반)에서 쟀습니다.
- **하지 않은 것**: 스크린리더(NVDA, 센스리더, VoiceOver) 실사용, 실제 모바일 기기, 브라우저 확대 기능 자체(320px 화면으로 대신함), 고대비 모드.

## 개선 권장(미흡은 아님)

1. **확산 타임라인 스크롤 영역**(`SpreadViz.tsx:45`): 지금은 Chrome이 스크롤 영역을 자동으로 초점 가능하게 만들어 주는 덕분에 키보드로 움직일 수 있습니다. 코드에서 직접 보장하려면 `tabIndex={0}`, `role="region"`, `aria-label="지역별 확산 타임라인(가로 스크롤)"`을 붙입니다. 그러면 axe 위반도 사라지고, 초점을 받았을 때 보조기술이 영역 이름을 읽습니다.
2. **각주 팝오버를 닫을 때 초점**(`Footnote.tsx:119-123`): 팝오버 안의 "출처 목록"에 초점이 있을 때 Escape를 누르면 팝오버가 사라지면서 초점이 문서 처음(`body`)으로 갑니다. 다음 Tab은 다음 각주로 이어지지만 스크린리더 사용자는 위치를 잃을 수 있습니다. 닫을 때 각주 버튼으로 초점을 돌려주는 편이 낫습니다.
3. **목차에서 챕터로 이동할 때 초점**: 푸터 버튼으로 이동하면 초점이 본문으로 갑니다. 그런데 목차 대화상자에서 챕터를 고르면, 본문으로 옮긴 초점(`Layout.tsx:255-258`)이 대화상자가 닫히면서 "목차" 버튼으로 되돌아갑니다(`Layout.tsx:170-173`, 기본 dialog 동작). 페이지 맨 위라 이용에는 문제가 없습니다. README는 이 동작대로 고쳤지만, CASE_STUDY의 "라우트가 바뀌면 본문으로 … 포커스를 옮깁니다"는 아직 예외를 적지 않았습니다.
4. **어두운 바탕의 초점 테두리**: 남색 바탕(표지 "읽기 시작", 푸터)에서 #C43048 테두리의 대비가 2.94:1입니다. 보이기는 하지만, 어두운 구역에서는 밝은 색 테두리를 쓰면 더 잘 보입니다.
5. **제목 단계**: 위 '제목 구조' 메모의 2곳은 h2를 넣거나 단계를 한 칸씩 내리면 axe `heading-order` 표시가 사라집니다.
6. **인디고 도식 레이블**(`IndigoViz.tsx:66-68`): `<output>`을 `<label>` 밖으로 빼면 html-validate 경고가 사라집니다. 지금도 슬라이더 이름은 "마모 0%"로 잘 읽힙니다.
7. **실밥 알림**: 알림에 마우스를 올리거나 초점이 있을 때는 사라지는 시간을 멈추면, 행동 버튼을 누르려던 사용자가 놓치지 않습니다.
8. **좁은 화면의 분해도 라벨**: 375px에서는 680 단위 도식이 약 285px로 줄어 라벨 글자가 약 5px로 그려집니다. 정보는 HTML 범례에 있지만, 좁은 화면에서는 도식 라벨을 숨기고 범례를 쓰는 편이 명확합니다.
